Things I've Built

Sana training compliance automation

AppScript / API

People were quietly falling behind on required training with no one tracking it. Now overdue training surfaces automatically, before it becomes a compliance problem.

Problem: Required Sana trainings had no reliable tracking — people fell behind and nobody noticed until it was flagged much later, usually manually.

Build: Built an automation that checks training completion status and flags who's overdue, so the gap gets caught early instead of surfacing downstream.

Outcome: Overdue training is now visible automatically instead of relying on someone remembering to check.

Ashby referral SLA automation

AppScript / Ashby API / Slack

Referrals were sitting untouched for weeks during a program we were actively reviving. Now recruiters get pinged directly, and leads get looped in if it keeps happening.

Problem: While reviving the referral program, we noticed referred candidates sitting in the first pipeline stage far too long — the exact opposite of the priority we wanted to give them.

Build: Pulled data from the Ashby API, used Claude to help write the AppScript logic, and connected it to Slack. Recruiters get pinged if a referral sits more than 5 days untouched; their lead gets pinged if it happens repeatedly over 2 months.

Outcome: Referrals now get chased automatically instead of relying on someone happening to notice — with a built-in escalation path if the pattern repeats.

Debugging & hardening onboarding automations

Error handling / Testing

Inherited a set of onboarding automations that failed silently. Added proper error messages and tests so failures surface immediately instead of getting discovered days later.

Problem: Existing onboarding automations would occasionally break, but with no error messaging — failures went unnoticed until someone downstream flagged a new joiner had fallen through the cracks.

Build: Went through the existing automation code, added meaningful error messages at the points most likely to fail, and added tests to catch issues before they hit production.

Outcome: Failures are now visible and traceable instead of silent — the system tells us when something breaks rather than a new joiner finding out the hard way.
